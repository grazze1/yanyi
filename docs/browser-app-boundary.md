# 浏览器插件与桌面 App 的职责边界

## 1. 问题

Popup 底部曾有四个大按钮：术语库、工作区、历史、设置。它们都跳转到桌面管理端，
却占据了 Popup 的主要空间，并把管理功能混入即时阅读流程。

## 2. 浏览器插件

只负责**当前页面的即时阅读**：

- 当前页面翻译（开始 / 暂停 / 继续 / 取消 / 还原）
- 当前选区翻译
- 询问研译（含解释、总结等快捷意图）
- Side Panel
- 当前 conversation
- 模型临时选择
- 页面翻译状态与扫描报告
- 来源跳转

### Popup 保留

```text
服务连接状态
翻译此页面
打开 Side Panel
翻译模式
页面语言
领域与技术标签
模型预设
页面翻译状态 / 扫描报告
⋯（溢出菜单）
```

`⋯` 中提供：

```text
打开研译管理端
诊断
```

并附一行说明：术语库、工作区、历史与完整设置在研译桌面端管理。

### Popup 删除

| 控件                 | 去向                                         |
| -------------------- | -------------------------------------------- |
| 术语库（底部大按钮） | 桌面 App                                     |
| 工作区（底部大按钮） | 桌面 App                                     |
| 历史（底部大按钮）   | Side Panel（当前会话）+ 桌面 App（完整管理） |
| 设置（底部大按钮）   | `⋯` → 管理端 / 诊断                          |
| 固定为侧边栏（图钉） | 与“打开侧边栏”重复，删除                     |

## 3. 桌面 App

负责管理与长期数据：

- API 与模型配置
- 全局记忆
- 术语库
- 工作区
- 历史管理
- 网站规则
- 数据导入导出
- 日志
- 诊断
- 数据库

不重复设计两套管理系统：浏览器端不提供术语库编辑、工作区管理或完整历史管理界面。

## 4. 历史入口

历史聊天主要在 Side Panel（当前站点会话）与桌面 App（跨站点完整历史）。
Popup 不承担完整导航。

## 5. 浏览器特定设置

确实需要的浏览器侧设置放在 `⋯`，点击后是“浏览器插件设置与诊断”页
（`options.html`），而不是桌面 App 的完整管理系统。

## 6. 事件总线

浏览器与桌面共享同一 Native Host 与同一 SQLite：

```text
Popup / Side Panel / 浮窗
  ↓ runtime.sendMessage / tabs.sendMessage
service worker
  ↓ runtime.connectNative（长连接）
Native Host（唯一写库者）
  ↓
SQLite（WAL）
  ↑
桌面 App（Tauri commands）
```

因此“同一站点会话”“全局记忆”“模型目录”在两端天然一致，不需要额外同步协议。

## 7. 验收

E2E `Edge fixture build renders core states and pages at 150% scale` 断言：

- `.secondary-nav` 数量为 0。
- 名为“术语库”“工作区”“历史”的按钮数量为 0。
- “翻译此页面”“打开侧边栏”可见。
- `⋯` 展开后“打开研译管理端”“诊断”可见。
- 360–420 px 宽度下无横向溢出。
